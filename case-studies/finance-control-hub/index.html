Evidence and privacy: The workflow was inspired by an operational finance problem. The original financial files were not provided; all vendors, invoice lines, references, amounts and test records in this public demo were generated for this case study. The prototype was not deployed to the originating business, and no private people or messages appear here.

The work to improve

Finance needed to compare vendor invoice charges with three operational exports: HAWB, MAWB and Accrue Cost. Those files describe connected parts of a shipment, but invoice lines do not always carry one consistent key or one clean one-to-one amount.

Current problem

Manual cross-referencing absorbs attention

An analyst opens several reports, searches by job or air-waybill reference, translates vendor-specific charge codes, compares currencies and amounts, then records missing POs, duplicates and unresolved cases by hand.

What makes a match difficult

Identifiers and financial meaning do not line up neatly

A charge may reference a Job ID, HAWB or MAWB; one invoice line may cover multiple accruals; several invoice lines can form one consolidated charge. Missing POs, tax treatment, currency and duplicate records can make an apparently close match unsafe.

Analysis decision: treat “find something similar” as insufficient. A match must preserve source lineage, resolve to a shipment, use a configured vendor/charge rule, respect currency and PO controls, avoid reuse of a record, and explain the amount comparison.

Product requirements and source model

The demo represents the records needed to reconcile and explain a decision. Counts describe this generated test batch, not historical client files. Field names are proposed simulation schemas, not official CargoWise report definitions.

Command and import: A natural-language instruction shares one intake surface with local file selection and drag-and-drop. The demo accepts a complete JSON batch or four canonical CSV sources, with an optional vendor-code map. Files are parsed and stored in this browser. The current batch is backed up before replacement and can be restored.

Where rules, AI and people belong

ResponsibilitySystem ownerFinance Control Hub behavior
Normalization and calculationDeterministic engineNormalize case and punctuation, resolve source links, map only configured vendor codes, calculate variances and detect duplicate fingerprints.
Defensible matchingDeterministic engineRequire unique shipment/vendor/charge/currency evidence; apply only the configured 0.05 rounding tolerance; reserve matched records so they cannot be allocated twice.
Unstructured interpretationOptional model assistA simulated, provider-neutral suggestion may interpret a charge description. It never writes a mapping or financial match and always remains labeled as unconfirmed.
Ambiguity and financial exceptionsFinance analystMissing PO, large variance, duplicate, tax/currency mismatch, conflicting references and grouped charges remain in a review queue with source evidence.
Export releaseFinance approverEligible rows are previewed. A person attests and downloads the illustrative CSV; no CargoWise record is posted or modified.
AI boundary: this public demo makes no live LLM call. Command interpretation uses a supported local action registry; matching is deterministic. A real model gateway could later use an organization-selected provider for bounded text interpretation, without changing the financial authority model.

Runtime

80 ms median · 284 ms browser run

Observed median across 7 local engine runs; the deployed browser session evaluated the 4,000-line batch in 284 ms. Demo execution only, not an operational SLA or measured business-time saving.

Interpretation: These results validate the engine against deliberately constructed scenarios, not a production sample. The generator and answer key share the scenario design; the next validation step is blind testing against representative, approved real records and Finance adjudication.

Business value and limits

Intended operational change

Move analyst time from repetitive cross-file searching toward exception investigation, evidence review and controlled release. An earlier estimate suggested at least two hours per working day might be recoverable; it is an unvalidated projection, not a measured saving.

Not claimed

No real source files were supplied, no historical accuracy or time baseline was measured, and this prototype was not deployed at the originating business. The generated dataset, matching results and runtime are demo evidence only.

Import-format limit: The downloadable CSV is an illustrative CargoWise-style mapping. No official EDI spreadsheet template was supplied or validated, so the output must not be treated as production-compatible.
